Snooze & dismiss — quick actions

Two small popovers, one component, anchored to whichever control was pressed. No drawer, no desk, no page change.
The bug is mine. I specified that every list action "opens the same desk the drawer uses, and opens the drawer behind it" so the desk would have a host and the ghost rung a rail. That's right for Record response and Mark sent, which compose a record and want the timeline visible — and wrong for snooze and dismiss, which are one decision each. Those two become quick popovers everywhere they appear.

3 · The rules

Snooze writes no activity. It moves the reminder date only — `reconcileNudge` and nothing else. The timeline is unchanged, the status is unchanged, "Since then" gains no icon. Receipt toast with Undo restores the previous date.
Nudge writes an activity. Draft, copy, Nudged rung, reminder rescheduled. Stays in the desk because it composes something.
Close writes one activity with the chosen reason, dated today, and retires the nudge. If the writer needs a different date or a note, the popover's footer sends them to the query — the quick path stays quick and the full path stays available.
Availability. Snooze appears only where a reminder exists or could (agent-side, open); Close on any open query; both absent on closed. Same predicate as everywhere else — one `queryVerbs`.
Anchoring. The popover opens against the control pressed and closes on Esc, outside click, or choosing; focus returns to the control. It never opens the drawer, never moves the page, and on the list it does not change the row's selection.
