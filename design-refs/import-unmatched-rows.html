CSV import — what happens to a row that doesn't match

Ruling: import every row, and say what didn't resolve. Skipping silently leaves a writer believing their data is there; inventing an id (ms-seed-fantasy) leaves the row real but invisible in every scope. Neither is acceptable — so an unmatched row lands, is flagged, and is resolvable in one place.

2 · What replaces the invented ids

The three siblings
Each fallback becomes a real state on the record, not a pointer to a fiction.
ms-seed-fantasy
→ the query holds no manuscript and is listed under Unassigned, which is visible in every scope. It cannot disappear.
agent-seed-alex
→ the query holds the agency and whatever name the row gave, as an unlinked contact. Agent-derived figures read "not recorded", not blank.
q-seed-fantasy
→ an activity with no resolvable query is not imported, and says so by row number. This is the one case where dropping is right: an event with nothing to attach to isn't a record, it's an orphan.
