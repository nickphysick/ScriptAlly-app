The empty description

You're right that it reads as a line that failed to load — and right that versions decide it, since a note-less version is the ordinary state, not the exception. Three answers below, each shown across all three cases: a pasted letter, an attached file, and a version with no note.
Also fixed in all three: the source line's two registers — Empty against not yet in a package — now read as one grammar; and Post-R&R no longer wraps, because the usage phrase moved off the source slot.

A · Collapse it

No band, no reservation
The card is as tall as it has something to say. Nothing is reserved, so nothing looks missing — an attachment card is simply shorter. The cost: cards in a row stop matching height, which on a two-column grid means a ragged bottom edge.

B · The file is the content

Recommended
An attachment has something to show — the file. Where there is no text, the description band holds a document plate: icon, filename, and its kind. The card keeps its height, and the space stops being empty because it stopped being the wrong question. A version with no note still says so in words, because a version genuinely has nothing else to offer.

The source line, one grammar. 412 words / Attached file / Latest on the left — what this material is. In 2 / Not in a package on the right — where it is used. The old Empty was a state masquerading as a source, and not yet in a package was a usage phrase sitting in the source slot, which is why Post-R&R was the only card that wrapped.
My pick is B: it is the only one where the space earns its height on an attachment, and it degrades to C's sentence on a version, which is the case with genuinely nothing to show. A is honest but gives a ragged grid, and the two-column layout is what makes the library scannable.
