Query attachments — either a package, or materials

Three faults, one cause. The block showed a package and a loose row at once; package chips showed generic type names instead of the materials actually in the package; and editing a package didn't change the query. All three come from the same missing rule — what a package means once it has been sent.

The rule that fixes it

Append-only, like the rest of the app
A package is freely editable until its first send. After that it locks. Want a different combination? Duplicate it into a new package. Because a sent package can never change, the query can always show its live contents and can never lie about what an agent received — so there is no snapshot, no divergence, and no stale copy to explain.
Why not simply live-update everything? Send Standard UK to twelve agents, later swap its letter, and tracking would claim all twelve received a letter they never saw. That is the one thing this feature exists to tell you, so it cannot be allowed to drift.
