Sort, group and filter

Two panels, both live. Sort & group answers "in what order, and gathered how"; Filter answers "which ones". Active filters become chips under the header — removable individually, cleared together — and the footer always says how many you're looking at out of how many exist. Everything persists per user in the list's view preferences.

Group comes first because it is the primary sort. Grouping decides the big shape of the list; ordering only runs inside each group, so the panel reads top-down in the order the list is actually built. Conflating them is how most task apps end up with "sort by agent" quietly destroying the urgency groups. Here the groups stay unless you say otherwise, and sorting reorders inside them — so "longest waiting" within Needs you now is one click, and "everything by agent" is Group → Agent.

Group by Agent is the smart one. It turns the list into "what do I owe each person" — every send, nudge and close for Jonathan Marsh under one head. Group by Manuscript does the same for Pro writers with several books; on a one-manuscript account it's hidden, not greyed.

Filter counts are conditional — each option shows how many tasks it would leave given the filters already set, so a choice that would empty the list says "0" before you make it. The three "also show" toggles (snoozed, dismissed, muted) are the only ones that widen the list; everything else narrows.

Chips carry the facet name in mono so "Jonathan Marsh" can't be mistaken for a search term, and the footer reads "6 of 18" whenever anything is hiding rows. An empty result says why and offers the one-click fix.

What's deliberately absent: saved views (premature), a date-range picker (the wait column and sort cover it), and multi-column sort (nobody asks for it and it's unreadable). The existing AnchoredPanel mechanism draws both panels; the list's todoPrefs.listView already persists sort — group and filters join it.
