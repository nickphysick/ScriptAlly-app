As well as, not instead of — because a package is a filler, not a container. Choosing one writes its items into the send's materials as ordinary pills: individually editable, individually removable, sitting beside anything already attached. The send's record stays one flat list of what actually went, which is what materialsSent is. No second kind of attachment, no opaque bundle pill that hides its contents.

The decision that matters is snapshot, not reference. Attaching copies the package's items as they are today. If the package is edited next month, this send does not change — it records what was sent, and a reference would quietly rewrite history every time the package evolved. The only stored trace of the package is a small origin tag on the send (3 items from UK standard), which is provenance, not a live link — and the pills work identically with or without it.

Overlaps are declared in the picker, not discovered after. Each package row shows its contents, and if an item collides with something already attached, the row says what will happen before you choose. Attach never silently replaces or silently skips.

No page-leaving. The picker is one more popover in the existing chain; Manage packages… is the only route out, clearly labelled as one. Undo on the origin tag removes the package's items in one action — the items it brought, not anything you attached separately.
