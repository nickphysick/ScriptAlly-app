A busy query — two years, ten events, a nudge, an R&R and a resubmission
  • A · One rhythm. Every event on the same rail with the same gap, and minor events (nudges, notes) reduced to a small hollow marker and one line of body text. Simplest, and the small marker is what stops a nudge claiming the same weight as a request.
  • B · Chaptered. The same rail, grouped into exchanges — The query, The partial, Revise and resubmit, The full — with a rule between. This is how a writer actually remembers a query: not as ten events but as four rounds. Best on a long history; on a two-event query the labels would be noise, so it needs a rule about when they appear.
  • C · Date column. Dates move to a left column with the weekday beneath, so the eye can scan chronology without reading titles. Most log-like and the most precise; it costs ~86px of width, which matters when the pane is 60% of the page.
  • D · Event cards. Each substantive event sits on a tinted panel; minor events stay bare. The chips gain a surface to sit on, which is the clearest of the four for materials — but ten panels in a column starts to look like a feed.

What all four fix. One rhythm regardless of what an event carries; the connector running marker to marker rather than floating; a distinct treatment for minor events so nudges and notes stop competing with requests; and chips grouped under the send they belong to.

My pick: B, with A's minor-event treatment. Chaptering is the only option that adds meaning rather than arranging it — and on a query this busy it turns a wall into four short stories. ⚠️ It needs a threshold: chapter labels only once a query has more than one exchange, otherwise a fresh query gets a heading saying The query above a single line.
