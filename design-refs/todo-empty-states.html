GButton states — the disabled grammar
Disabled is flatter than any live button: paper fill (it sinks into the page where white pops), hairline border, faint text, no shadow, not-allowed cursor. Never dashed (dashed = invitation to add) and never just opacity (a dimmed live button still reads as clickable).

Notes on the system

The derivation is simple and already available: new-desk (A) = zero queries AND zero agents; per-reel clears (B/C/D) = that lane's derived set is empty while the app has data; desk-cleared (E) = all three empty AND `clearedToday` is non-empty — the done-log is what earns the moment. No new state is stored anywhere; these are all views over what exists.

Voice rule across all of them: empty-because-done states never apologise and never use the word "empty" — they report the truth ("all 7 are with their agents") and hand you back to the writing. The Caveat handwriting appears exactly once per state, as the human aside. And B's count ("all 7 live queries") is real data doing reassurance work — worth the one extra read it costs.

If these land, they fold into the retoken prompt as one more phase (or a small follow-up pack if the retoken's already run) — all presentational, all derived.
