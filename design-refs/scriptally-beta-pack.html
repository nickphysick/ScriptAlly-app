ScriptAlly · Beta readiness

What beta users need that doesn't exist yet

Five surfaces. Two of them aren't really features — they're the launch blockers from the audit wearing a UI, and the privacy policy already promises both. The other three are what makes a beta a beta rather than an early launch.

01Invite gateNew build

A beta you can't close isn't a beta. The waitlist on the holding page already collects addresses — this turns one into an invite code that gates account creation, so you control the intake rate and know who everyone is.

State · code required

No code yet? Join the waiting list — we're letting people in a handful at a time.

State · code not recognised

That code isn't one of ours, or it's already been used. Check the email we sent, or ask us to look it up.

02Beta stripNew build

Sets expectations once, honestly, without an anxious modal. Sits above the workspace, dismissible per session, and gives the known-issues list somewhere to live so people stop reporting the same three things.

Beta

You're using ScriptAlly before it's finished. Your data is real and kept safely — but expect the odd rough edge, and tell us when you find one. What we already know about.

03Feedback dockNew build

The single highest-value thing on this page. A beta without a one-click report route produces silence, and silence reads as "it's fine" right up until people stop signing in. It captures the page, the browser and the account automatically, so you don't have to ask.
