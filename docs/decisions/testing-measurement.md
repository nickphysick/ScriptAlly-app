### From “Working discipline (READ FIRST — repo hygiene rules, locked 8 Jul; supersedes the old "Mul” (CLAUDE.md lines 6–6)

- **⚠️ A RENDER HARNESS LOADS `dist/assets/index-*.css`, NEVER A HAND-PICKED LIST OF SOURCES.** Inlining `index.css` + the component's stylesheets omits **Tailwind's preflight**, so every box in the harness is `content-box` while every box in the app is `border-box`. On 6 Aug that difference produced a *measured, locked and deployed* fix that was wrong in the opposite direction: padding-only measured as aligned (48.0) in the harness and left the pill at 41.0 against the bar's 48.0 in the app, while the correct shape measured as an overshoot. **Every number was real; they described a page the app never serves.** A rule whose maths depends on the box model should also **declare `box-sizing` itself** rather than inherit it. Related measurement traps in that pane: `getBoundingClientRect` returns **zeros** (its `documentElement.clientHeight` is 0, so `100vh` collapses) — use `offsetTop`/`offsetHeight`, pin explicit pixel dimensions instead of `100vh`, and take a screenshot first to force layout or the first JS call still reads zeros.

### From “Working discipline (READ FIRST — repo hygiene rules, locked 8 Jul; supersedes the old "Mul” (CLAUDE.md lines 8–8)

- **⚠️ AND BEFORE BLAMING THE REPO FOR ANY CI ODDITY, CHECK `githubstatus.com`.** That day's cause was a **critical GitHub Actions incident from 15:22 UTC** — *"workflow runs are failing or delayed, and some queued jobs may time out"*, plus webhook delays that meant a push to `main` produced **no run at all**. The correlation was exact: every run before 15:22 passed or failed for a real reason; every anomaly is after it. The first diagnosis — that bursts of commits starved the queue — was **wrong**, and the evidence for it (the starved run being the older of two in flight) was a coincidence of timing. One `curl` of the status API would have led with the answer instead of arriving at it third. **`workflow_dispatch` is on `ci.yml`** for the tail of exactly this: `gh workflow run CI --ref main` verifies the tip without an empty commit when a run went missing. **The tell is `runner_name`** — `gh api repos/<o>/<r>/actions/runs/<id>/jobs`: a job that ran and genuinely failed names the machine that ran it and has steps; a starved one has `""` and no steps at all. Two defences are now in the workflows and neither should be removed casually: **`ci.yml` carries a per-ref `concurrency` group with `cancel-in-progress`** (both starvations were the OLDER of two runs in flight during a commit burst — main is linear, so verifying the tip verifies everything under it, and a concurrency-cancelled run ends `cancelled`, so it does not notify), and **`ci-retry.yml`** re-runs a failed run ONCE, but only when *every* job **executed zero steps**. (That discriminator started as "no runner was ever assigned" and **missed the very next infrastructure failure** — *"The hosted runner lost communication with the server"*, which HAS a runner name and still runs nothing. Zero completed steps is the honest signal: a real code failure always leaves steps behind.) **Retrying on `failure` alone would re-run real red builds until they went green by luck** — the discriminator is the whole point, and it was verified against the two real starved runs and the one real test failure before it shipped.

### From “Working discipline (READ FIRST — repo hygiene rules, locked 8 Jul; supersedes the old "Mul” (CLAUDE.md lines 33–34)

- **⚠️ A SOURCE SLICER MUST STRIP COMMENTS BEFORE IT COUNTS — INCLUDING WHEN THE COMMENT IS YOURS, EXPLAINING THE TRAP.** *(10 Sep, the second red in a row from one fix.)* `tasksViewport`'s `rule()` deliberately does not strip (its own note explains why and asks that it be left alone), so it reads raw source. A comment naming a selector the way CSS does — the class, then a brace — **is a match for that selector**. The paragraph written to explain the grouped-selector trap it had just fallen into became the next failure. Prose about a selector spells it without the brace.
- **⚠️ A ROLLING-WINDOW BOARD'S DOM IS DATE-BOUND, SO A BYTE-IDENTICAL REFERENCE HAS A SHELF LIFE OF HOURS.** *(10 Sep.)* The calendar draws a 90-day window centred on TODAY. A `outerHTML` reference captured yesterday differed at all three widths this morning with no code change at all — first rail date `29` → `30`, month labels down 0.5–1.0 day units, every bar left by ~9px (one day on an 808px/90-day lane is 8.98px), heights unchanged. **The standing rule: capture the reference from UNMODIFIED HEAD at the start of each run, and never carry one between runs.** A carried reference makes the next session read a date shift as damage from their own change — a whole day chasing a diff nobody caused.

### From “Working discipline (READ FIRST — repo hygiene rules, locked 8 Jul; supersedes the old "Mul” (CLAUDE.md lines 36–36)

- **⚠️ A LOCK READING CSS AS SOURCE PROVES A RULE WAS WRITTEN, NEVER THAT IT REACHED AN ELEMENT.** The pair retired on 18 Aug required `flex: 0 0 auto` on `.tpl-head` by searching the stylesheet text — and passed for months over a declaration the browser was discarding, about a class no component renders. **Doubly vacuous: a property that never applied, to an element that never existed.** 21 such assertions across 13 suites remain and are fine as they stand — a source lock is the right tool for *"this token is still emitted"* or *"this selector is not restated"*. It is the wrong tool for *"this element ends up laid out like so"*: that claim is measured on a rendered page (`npm run e2e`), never read out of a file. Forbidding a class in a sheet is a different and legitimate claim from requiring a property on it.

### From “Deployment” (CLAUDE.md lines 557–560)

- **⚠️ A PIXEL SWEEP THAT EXCLUDES REGIONS MUST MEASURE THEM, NEVER TYPE THEM — AND A WRONG EXCLUSION FAILS IN THE FLATTERING DIRECTION.** *(4 Sep, the slim bar's opacity sweep. Two runs, two wrong exclusions, both of which would have PASSED on a bar that was genuinely see-through, because they were sampling somewhere else.)* First a fixed strip "between the measure's left edge and the text", which ran into the ICON — there is no ground there, because the measure is inset by the gutter and the picture starts at it. Then a whole-box sweep, which read the DESK at (2,3): `.ws-window` clips at a 16px radius and the band's top edge is the window's, so a pixel inside that arc is ground showing past the curve.
  - **THE FIX IS TO ASK THE BROWSER.** The children's rects for the ink, the computed `border-radius` for the corners — so both are correct at every width, on every page, and after any retone, rather than tuned to the one screenshot that prompted them.
- **⚠️ WHERE A CHEAP GUARD AND AN EXPENSIVE ONE GUARD THE SAME CLAIM, PROVE EACH RED ON A FAULT THE OTHER CANNOT SEE — OR THE EXPENSIVE ONE IS DECORATION.** *(4 Sep, and it is the masked-red rule from the other end: there an earlier failing assertion hid the ones below it; here an earlier PASSING guard hides that the one below was never exercised.)* The bar's opacity is guarded twice: a computed-style read of `backgroundColor`, and an 857-point pixel sweep. **Adding alpha proves only the first** — it fires, the sweep never runs, and a green is recorded for a check nobody has watched work. The mutation that proves the sweep is a bar that is OPAQUE but stacked below the content: `backgroundColor` reads a perfectly correct `rgb(254, 252, 250)` and 767 of 857 points come back white.
  - **THE TELL IS TWO ASSERTIONS ABOUT ONE PROPERTY AT DIFFERENT COSTS.** Ask what fault each catches that the other does not; if you cannot name one for the expensive check, it is not a second guard, it is a second opinion.

### From “Conventions & invariants” (CLAUDE.md lines 647–655)

- **⚠️ A CASE WHOSE FIRST ASSERTION IS FAILING IS NOT GREEN — IT IS SILENT, AND EVERY ASSERTION BELOW IT IS UNPROVED.** *(30 Aug: deleting one lock's leading claims exposed **four** reds underneath it, in three different files, that had been red for four commits.)* This is the standing "presumed vacuous until re-proved red" rule from the other end: there, a probe finds no element and reports no offence; here, the probe never runs at all because an earlier `expect` threw. **The report says `1 failed` either way, and the count of what was actually checked is invisible.**
  - **THE EIGHT, because the shape is only recognisable from the set.** A height derivation reading `.wsh`'s padding — `0` since the format moved the air to `.wsh-body` — so the sum was 88px short from the day it landed. Behind THAT, a cross-page equality over raw height, which asserts COPY: two pages whose description wrapped to a second line measured 23.2px taller, and six correct mastheads were reported as disagreeing. And two cases running a `settled` posture that no longer exists: scrolling removes the masthead rather than tightening it, so one clipped a screenshot to a box above the viewport (*"Clipped area is either empty or outside the resulting image"*) and the other reported ink outside its clipping ancestor by 340px, **which is a true statement about nothing**. Behind those, a mark-size claim expecting `[52]` while every page reported the "no mark" sentinel; and behind THAT, a carve-out table exempting two pages from the type scale, the mark and the height, all three of which they now match exactly.
  - **⚠️ AND THEY CAME OUT ONE AT A TIME, WHICH IS THE PART TO EXPECT.** Fixing the derivation did not make the file green — it made the NEXT assertion reachable, and that one was wrong too, eight times over. **Budget for a chain, not a fix.**
  - **⚠️ AND A SPREAD THAT HAS BEEN LOOSENED ONCE WILL BE LOOSENED AGAIN.** The control row's position allowed "at most two distinct heights", raised from one to accommodate a real outlier rather than diagnose it; a third arrived (a description wrapping) and the honest answer was not a third slot but a RELATIONSHIP — the row's top IS the masthead's height, per page, to the pixel. **A tolerance cannot be satisfied by two pages being wrong in the same direction; an equality between two measured things cannot be satisfied at all.**
  - **⚠️ A CARVE-OUT NAMING PAGES THAT NO LONGER DIFFER SILENTLY SHRINKS THE POPULATION.** Three claims here were being asserted over EIGHT pages while reading as ten, because a table exempted two from a rule they had since come to obey. The exemption cost nothing to keep and quietly bought less coverage every pass; **a carve-out is re-measured, not inherited.**
  - **THE PRACTICE: when a case goes red, fix it and RUN IT AGAIN before believing the file.** One red can be hiding an arbitrary number behind it, and the ones behind are by definition the ones nobody has looked at recently. The same applies to a case you are deleting: **the assertions it was standing in front of are unproved, not passing.**
- **⚠️ A CONTROL THAT APPEARS INERT MAY BE WORKING PERFECTLY, WITH SOMETHING UNDOING IT IN THE SAME FRAME.** *(30 Aug, Query Centre's `← All queries`.)* The link navigated, the param was removed, and an effect elsewhere in the component saw the param go, failed its lookup and restored the selection from `localStorage` — **inside the same tick**. Nothing about the control was wrong; a reader watching the screen sees a dead button, and a reader reading the handler finds nothing to fix.
  - **THE TELL IS THAT THE CONTROL'S OWN CODE IS SHORT AND OBVIOUSLY CORRECT.** When a one-line handler "does not work", stop reading the handler. Ask what ELSE reacts to the thing it just changed — an effect on the same state, a `useEffect` with a stale dependency list, a restore from storage, a parent re-deriving a prop.
  - **THE INSTRUMENT IS A ROUND TRIP, NEVER THREE SEPARATE CHECKS.** Arriving with the param worked; clicking a card worked; the transition OUT was never asserted, so every leg was individually green while the page was unusable. **A case that asserts the states without driving between them cannot see this class at all** — it is the composed-result rule (below) with time as the composition.

### From “Conventions & invariants” (CLAUDE.md lines 659–663)

- **⚠️ A SOURCE LOCK CAN ONLY ASSERT WHAT THE SOURCE SAYS — GEOMETRY BELONGS IN A MEASUREMENT.** *(30 Aug, Query Centre's command row. The sharpest form yet of the "assert the claim, not the spelling" rule, because here the spelling was standing in for a claim of a completely different KIND.)* Two locks required `{listHead}` to appear AFTER `className="f12-list"` in the file. Neither cared about text order: both were standing in for *"the list's controls sit over the list column rather than in a page-wide strip"* — the correction that retired such a strip in the first place. The head then moved one level UP, into a grid cell over the same column, and **the source order inverted while the law it stood for became, if anything, more true**.
  - **THE TELL IS A SOURCE LOCK WHOSE FAILURE MESSAGE DESCRIBES A POSITION ON SCREEN.** "The head escaped the list column" is not a fact about a file; `indexOf` cannot see a column. If the message you would write mentions above, below, over, beside, aligned or spans, the claim is geometric and the lock is in the wrong file.
  - **THE SPLIT: source order belongs in a source lock** (*this element is mounted*, *this token is still emitted*, *no strip spans both columns*); **position belongs in a measurement** (*the left cell's box IS the list column's box, to the pixel, at 1280 and 1920*). The second is also the stronger claim — it asserts two boxes are the same box rather than that two declarations read the same token, which is what "same grid" actually means.
  - **AND THE PROXY IS WHAT MAKES IT EXPENSIVE.** A lock pinning a spelling fails on every legitimate edit and trains the next reader to rebaseline it without looking; a lock pinning a PROXY fails on an edit that made its own claim truer, which is worse — the honest response looks like weakening it.

### From “Conventions & invariants” (CLAUDE.md lines 691–696)

- **⚠️ THE QUERY LIST IS MANUSCRIPT-SCOPED, SO A DEFAULT-SCOPE CENSUS SILENTLY OMITS EVERY QUERY ON ANOTHER MANUSCRIPT — WHICH IS EXACTLY WHERE A STALE RENDER SURVIVES.** *(24 Aug, the Part D census.)* A sweep that clicks through the rows it can see reports a clean result about the subset it happened to be shown, and the omission is invisible because nothing states how many rows were skipped. **Sweep at scope All and REPORT THE COUNT SWEPT** — `44 of 44` is a census, `30 rows` is a sample wearing a census's clothes.
  - **⚠️ AND CHECK THE CONTROL EXISTS BEFORE BELIEVING YOU WIDENED ANYTHING.** Two of my own censuses said "scope All" and clicked nothing: `getByRole("button", { name: /^all$/i })` matched no control in that toolbar, and the guarded `if (await all.count())` made the miss silent. Those sweeps happened to be complete for a different reason — the list is not scoped by the shell's manuscript chip — so the counts stood and the stated reason for them was wrong. **A no-op widening step reads exactly like a successful one.**
  - **THE STRONGER FORM: compare the rendered row count against the STORED count.** `47 stored · 47 rendered · difference 0` cannot be satisfied by a filter you forgot to clear, and it is what caught `if (!agent || !ms) return false` dropping unresolvable rows at every scope.
- **⚠️ `force: true` ON A CLICK IS NEVER THE FIX FOR A TIMEOUT.** It skips Playwright's actionability check and dispatches at the coordinates the locator resolved to — which a hover-lift, a settle animation or a sticky reflow has already moved. **It opened a neighbouring control and reported correct code as broken:** a packages card's lift put `DUPLICATE` under the pointer and the click landed on `EDIT` (`title="EDIT PACKAGE"`), which read as the duplicate flow being wired to the wrong handler. **When a click times out, the element is telling you something** — it is covered, it is off-screen, it is a hidden mounted page's copy, or it has not settled. Fix that. Where a real overlay must be bypassed for a measurement, `el.evaluate((e) => e.click())` dispatches on the element itself and cannot land somewhere else.
- **⚠️ DISMISSIBLE CHROME HIDES LAYOUT FAULTS — when a bug reproduces in the harness but not by hand, suspect dismissed or persisted chrome before doubting the harness.** *(Same run.)* `BetaStrip` returns `null` once dismissed (`sessionStorage`), so the strip disappears, `.ws-main` starts at `y: 0`, and its `100vh` becomes momentarily correct. **Anyone who had clicked the × once saw a whole page and could never reproduce the fault; the harness gets a fresh session every run and therefore always saw it.** The offset was never a property of the chassis either — it was `(whatever sits above the shell) − 20`, so a banner of a different height would have changed it silently.

### From “Conventions & invariants” (CLAUDE.md lines 705–706)

- **⚠️ A CHECK THAT PASSES BECAUSE IT NEVER MEASURED THE THING IT NAMES — THE PRECONDITION GAP.** *(20 Aug, and it is the shape behind several faults in one pack, which is why it is stated as a family rather than as another example.)* An assertion names a state ("max scroll is unchanged **once the masthead has scrolled out of view**") but only measures the consequence, never the state. If the page never reaches that state the consequence is trivially true and the check goes green having tested nothing. **The measurement asserts the PRECONDITION first, then the claim.** Instances already in this file, all the same shape: `elementsFromPoint` outside the viewport returns an empty array, so a stacking probe is satisfied by `undefined` — assert the rect is on screen first; a `sliceBetween` whose end anchor is missing silently widens to the rest of the file — assert both anchors; a source lock reading prose instead of code — strip comments first.
  - **⚠️ AND IT BITES HARDEST ON A PROPERTY THAT HOLDS BY CONSTRUCTION.** When the invariance padding was deleted, max scroll became constant *because the masthead is content and changes no heights* — so there is nothing left to compensate and nothing left to get wrong. **That is precisely the property nobody thinks to check, and the construction is a paragraph of CSS anyone can edit.** Keep measuring it, and make it state its own precondition, or the day someone gives the masthead a height again the check will still be green.

- **⚠️ WHEN A REPORT NAMES SYMPTOMS, SCAN FOR THE FAULT CLASS — DO NOT TREAT ITS ELEMENT LIST AS THE SEARCH SPACE.** *(21 Aug.)* A clipping bug arrived described as "the top breadcrumb bar — ScriptAlly and the page name, both clipped". Probing those classes would have found the breadcrumb WHOLE (1.5×, uncropped) and fixed nothing: the clipped "ScriptAlly" was the SIDEBAR wordmark sitting in the same band, and a third site — the masthead title — was not in the report at all. **Scanning every Playfair leaf for the PROPERTY found all three.** A reporter names where they were looking; the fault is wherever the declaration was copied to.

### From “Conventions & invariants” (CLAUDE.md lines 715–718)

- **⚠️ WHEN A MEASUREMENT IS SLOWER THAN ANOTHER SESSION'S EDIT LOOP, NO AMOUNT OF REBUILDING WINS — THE TREE SPLIT IS NOT HYGIENE, IT IS THE ONLY WAY THE RUN COMPLETES.** *(20 Aug, the masthead pack's step 4.)* `dist/` and `src/` are shared across every session in a checkout, and `bundleGuard` refuses to measure a bundle whose sources changed after it was built — correctly, since the alternative is reporting your own edit as absent. A Playwright run over ten pages takes minutes; another session editing `src/` makes the bundle stale inside that window, and **every case after the first dies at sign-in.** Rebuilding and retrying is a race lost by construction.
  - **THE NUMBERS, BECAUSE "IT HELPED" UNDERSTATES IT:** the same six measurement files were UNFINISHABLE in the shared checkout and ran **12/12 in 3.9 minutes** in a worktree. Not slower — unwinnable.
  - **THE SHAPE:** `git worktree add --detach ../ScriptAlly-<task> HEAD`, copy the working changes across, symlink `node_modules`, build and `vite preview` on its own port, point the harness at it with `SA_E2E_BASE_URL`. **It is a MEASUREMENT environment — commits still come from the primary tree**, so direct-to-main is unchanged. `.env.local` and `tests/e2e/.auth/` have to be copied (both gitignored, both the dev-only harness account); say so in the report, and delete the second copy when the worktree goes.
  - **⚠️ AND CHECK FOR COLLISIONS BEFORE COPYING ANYTHING IN.** `git diff --name-only <your-last-commit>..HEAD -- <your files>` — if the other session has committed to a file you are about to overwrite with your working copy, you would silently destroy their work.

### From “Conventions & invariants” (CLAUDE.md lines 744–748)

- **⚠️ A PRESERVED NUMBER IS NOT A PRESERVED PLACE — WHERE A LAYOUT RESTRUCTURES, ASSERT THE ANCHOR, NEVER THE OFFSET.** *(To-do drawer round, Phase 2, 5 Sep. Filed beside the two coverage-assertion entries below because it is the same family one level up: there the fault hides under a FIRST-LEVEL scan, here it hides under a TOLERANCE.)* Opening the drawer folds every row from one line to two — 50px to 57.9px — so the same `scrollTop` lands somewhere else entirely. **Measured: `scrollTop` moved 140 → 138 while the row at the top of the port went from Ottoline Frayn's to Marcus Reed's.** Two pixels of drift and a whole row of movement, at a shallow scroll; deeper in the list it is a row per eight pixels of row above you.
  - **A TOLERANCE WOULD HAVE CALLED IT GREEN, AND THAT IS THE POINT.** `Math.abs(after - before) < 1` failed only by luck; anything from 3px up would have passed and shipped a list that quietly moves under the reader. **Assert the thing the reader can see** — *which row is at the top of the port* — because that cannot be satisfied by a coincidence of numbers, and because it is the claim the design actually makes.
  - **⚠️ AND SCROLL ANCHORING CANNOT SAVE A WHOLESALE RESTRUCTURE.** The browser compensates for content arriving or leaving; when EVERY row changes size at once it nudges and gives up — it moved 2px of a ~60px shift. **`overflow-anchor: none` is the wrong lever in the other direction** and this file already records why (the workspace's mini bar). Hold the anchor yourself: remember the row at the top and its offset within the port, restore it in a **layout** effect so nothing is painted in the wrong place.
  - **⚠️ CONFINE IT TO THE ONE STATE CHANGE THAT CAUSES IT.** `TaskList` restores only across the fold, and leaves anchoring alone everywhere else — a restore on every render would be a SECOND scroll model competing with the browser's, which is a worse bug than the one it fixes and much harder to see.
  - **THE GENERAL FORM: any layout that changes an item's size for all items at once invalidates the offset.** A fold, a density switch, a font-size change, a compact/comfortable toggle, a column becoming two lines. In each of those the number survives and the place does not.

### From “Conventions & invariants” (CLAUDE.md lines 771–812)

- **⚠️ HARNESSES ARE FOR BEFORE-AND-AFTER; "IS THE APP CORRECT" GOES THROUGH PLAYWRIGHT (`npm run e2e`).** A harness is a reconstruction of the page containing only what someone remembered to put in it, and **four separate harness results were wrong in a single day (12 Aug)** — each agreeing with itself while describing a page the app never serves: a `pkgw-mschip` class that exists nowhere, a stylesheet that 404'd and parsed to **zero rules**, a first-match slice that read a grouped stub instead of the real rule, and a `(?!100%)` lookahead that matches `100%`. **Harness agreement is not verification.** The split: a harness may answer *"did the change I just made do what I intended"*; only the running app answers *"is the app correct"*. `tests/e2e/` opens the deployed dev site signed in, suppresses transitions **with a stylesheet rule** (an inline style cannot reach a `::after`), and reads the real DOM. **⚠️ ITS ONE BLIND SPOT IS THE SCROLLBAR** — Chromium follows the macOS "show scroll bars" setting and NOTHING overrides it (measured: flags singular and plural, headed, full channel, injected `::-webkit-scrollbar`, `scrollbar-gutter: stable`, `scrollbar-width` — all 0px), so the one fault class that hid for a whole session is the one it cannot reproduce. Every report states the measured scrollbar width; a classic-scrollbar question needs a console run in Nick's own browser. **Credentials:** `SA_E2E_PASSWORD` in `.env.local`, and the saved `storageState` — both gitignored, and the ignore landed *before* the tool did.
- **⚠️ `bundleGuard` FAILED OPEN FOR EVERY LOCALHOST RUN, AND NOTHING SAID SO.** *(21 Aug.)* Its `servesBuiltBundle` ended `catch { return false }`, so **"could not reach the server" was reported as "not serving a built bundle"** — which the caller reads as permission to skip every check. **Proved, not suspected: the production project id was planted in `dist/assets` and a measurement passed.** And the server it could not reach was running the whole time — `vite preview` binds IPv4 only, Node resolves `localhost` to `::1` first and undici does not fall back, so `fetch` threw `fetch failed` against a server `curl` and Chromium both talk to happily. **Node and the browser disagree about `localhost`, so Node's failure to connect says nothing about the page being measured.** It now tries the literal host, then `127.0.0.1`, and if neither answers it **checks the bundle anyway**: refusing a good run costs a rebuild, passing a prod one is the incident the file's own header describes.
  - **⚠️ AND THE FAMILY IS NOT A CONSTANT — IT WENT THE OTHER WAY ON 7 SEP AND COST ABOUT AN HOUR.** The note above says `vite preview` binds IPv4 only; that day it bound **`[::1]` only**, so `curl 127.0.0.1` refused while `localhost` answered — the exact mirror image. **The measurable cost was not a failed run but a SLOW one:** `ensureSignedIn` calls the guard on every spec, the unreachable-family fetch does not fail fast, and runs that take **22 seconds** took **16 to 17 minutes**, three times, each looking like a hung page or a broken assertion. One died in `auth.setup`, one at a `toBeVisible`, one wrote no report at all — three different-looking faults, one cause.
  - **THE RULE IS TO BIND IT EXPLICITLY, NOT TO LEARN WHICH FAMILY IT PICKED.** `npx vite preview --port <p> --host 127.0.0.1` binds IPv4, and `SA_E2E_BASE_URL=http://127.0.0.1:<p>` then agrees with Node, `curl` and Chromium at once. Where a server is already running, `lsof -nP -iTCP:<port> -sTCP:LISTEN` names the family in one line — **check it before diagnosing anything else about a slow local measurement**, because every symptom of this points somewhere more interesting than the socket.
  - **⚠️ AND THE WAY IT GOT EXERCISED IS WORTH KNOWING: running the BUILD GATE inside the measurement worktree destroys the dev bundle.** `npx vite build` is production mode, so a routine gate check overwrote the dev `dist/` the preview server was serving, and the next measurements ran against prod — reported as "the bar measures 0px" and "no content landmark on the page", which read exactly like a broken page. **In a measurement worktree the build gate is `npm run build:dev`**, or rebuild dev before measuring again.
- **⚠️ A CRASHING LOCK IS NOT A FAILING LOCK — IT TELLS YOU NOTHING, AND IN A NOISY SUITE IT HIDES.** *(23 Aug.)* Three measurement cases dereferenced `.wsh` unguarded and died with `Cannot read properties of null` the day a page legitimately changed shape — it declined the shared masthead, which the grid's own prop type permits. **They were red on `main` for an unknown length of time and nobody noticed**, because a throw and an honest failure look identical in a run summary, and this repo's gate convention is "no worse than baseline" precisely because other streams' WIP may already be red. A genuinely broken lock disappears into that noise.
  - **THE GENERAL FORM:** any check that dereferences a **page-specific element** — a masthead, a toolbar, a named pane — will CRASH rather than FAIL the day a page stops rendering it. A crash names a line number; a failure names a property. Guard the read, turn the absence into a **reading** (`optedOut`, `hasRow`, `present`), and assert the population separately — both that enough pages were measured, and, where the absence is itself a decision, that its count is what you expect.
  - **⚠️ AND THE ABSENCE IS USUALLY THE MORE INTERESTING FACT.** A page silently leaving a system is exactly what a census exists to catch. The repair here reports "opted out" and asserts that count is **zero**, so the next one surfaces the decision instead of being absorbed by a skip — or, as happened, instead of taking three locks down with it.
- **⚠️ A COUNT IS NOT A REASON, AND PLAYWRIGHT'S LIST REPORTER DEFERS EVERY REASON TO THE END.** *(20 Sep, and it cost an hour of measurement plus a confident wrong story told three times.)* A 74-file run was watched by `grep -c ✘` while the count climbed — 20 red, 29, 47 — and a hypothesis about which suites had broken was built on top of it and reported. **116 of the 149 failures were `bundleGuard` refusing to measure a stale bundle.** Not one of them was a reading about the app. The rule this file already states — read the COUNTS, not the status line — has a second half: **a count is not a reason, and a run whose reasons you have not read is a run you cannot describe.** Either wait for the reporter's failure blocks, or grep the log for `Error:` before saying what a red means.
