## Manuscripts page — THE BOOK PROFILE (26 Aug, amended 27 Aug; ref = design-refs/manuscripts-scroll-page.html — the earlier `manuscripts-book-profile.html` is REMOVED, not superseded in place; SUPERSEDES the sage-plate tabbed pane below, whose four panes are DELETED from live code)
- **Five tabs, and the absence is the point: Overview · Journey · Comparable titles · Versions (Pro) · Notes.** **There is NO packages tab** — sample material points at a book version and packages never reference a version, so a tab here would advertise an edge that does not exist and must not be created. Packages reach this page as a footer link. **Only Versions is chipped**: comps are free (only the Scout is gated) and packages have no gate at all, so a chip on either sells a writer what they already own. Tab state is LOCAL — no route, no URL param, no persistence.
- **⚠️ THE TWO JOURNEY TRACKS MUST DISAGREE ABOUT THE SAME QUERY, and that is the feature.** `standingTrack` counts each query ONCE at its CURRENT point (seven stations + closed + unrecognised = total); `furthestTrack` counts each query ONCE at its FURTHEST-EVER point, open or closed (six rungs = total). A query that drew a full request and was then declined **stands at closed and reached full requested**. Making them agree would delete every request the writer has ever had the moment it closed. Both sums are locked as PROPERTIES over six status mixtures in `src/lib/manuscriptJourney.test.ts`, and both were proved red twice — once with the module missing, once against the natural mistakes (a cumulative standing track gave 31 against 10; a furthest track reading current status gave 1 against 10). **`furthestTrack` imports `analytics.buildRows` rather than re-deriving "reached"**, so this page and Analytics cannot disagree about the word.
- **⚠️ UNRECORDED IS NEVER FOLDED INTO A KNOWN, on all three version surfaces.** A sample with no `bookVersionId` gets its own line in the list ("counted here, not against any version above"), its own row in Requests by opening reading **`Not attributed`** — a request on an unrecorded opening cannot be attributed to one — and `Not recorded` in Who holds which version. Locked in `src/lib/unrecordedVersion.test.ts`, proved red twice (missing derivations; then a fold, caught by the reconciliation at 4 samples against 3). The failure is always silent and always flattering: folding makes a version look busier than it is, dropping makes the page state fewer samples than exist, and **both leave every total looking sane** — which is why the checks NAME the unrecorded ones rather than only checking the numbers add up.
- **⚠️ THE PERMANENT LIMITATION IS ON THE PAGE, VERBATIM** (`VERSION_LIMITATION`): the app records which version a sample was SENT AS and cannot check the text itself matches. Reported, not guaranteed. Without it the table reads as a promise about a manuscript's contents; it survives an empty table, because it is a fact about the feature and not about the rows.
- **⚠️ `Manuscript.elevatorPitch` IS NOT IN THE MANUSCRIPT-UPDATE ALLOWLIST, so the Overview's pitch card is READ-ONLY and `Edit pitch` is deliberately unbuilt.** The rules list is `title, genre, subGenres, ageCategory, wordCount, logline, comps, status, shelvedReason, statusChangedDate, notes, shelved, activePackageId, bookVersions` — a write carrying the key is denied in SILENCE (the affectedKeys gotcha). `overviewPane.test.tsx` READS firestore.rules and fails the day the allowlist gains it, which is the signal to build the control. `last edited` is in the ref and is not built either: nothing records when the pitch was written.
- **⚠️ NOTES ARE `UserTask` DOCUMENTS, SCOPED EXACTLY AND DATELESS.** `manuscriptNotes` takes items whose `manuscriptId` IS this one and which carry no `dueDate` and are not done. **An unattached note is not this book's** (`scopeTasks` keeps unscoped items in view, which is right for a board filter and wrong here), and **a dated item is a TASK** that belongs on the To-do list. That second filter is load-bearing rather than tidy: the Query Centre's `Remind me later` already writes `manuscriptId` and always sets `dueDate`, so without it every two-week nudge reminder would surface on the Notes tab as though the writer had put it there. `notesPane.test.tsx` reads Queries.tsx and fails if a scoped task ever stops carrying a date.
- **The shared container language lives in `src/components/containers/`** — `SectionHeader` (`.sa-sechead`, the tick is a PROP because packages wants one and this page does not) and `CappedCard` (which renders `CardBand`, imported from packages, never a copy). **The four cap tints are `--cap-slate/pink/sage/tan` at `:root`; packages' `--pkgt-pro/let/syn/sam` READ them.** One source of hexes, two vocabularies — the material names are true on a page whose cards ARE materials and a false claim anywhere else.
- **`ManuscriptPlate` has a `hero` variant** — it drops its mark, stat strip, action column and logline, and moves the status pill onto the title's row (a DOM change, not a flex reorder, so the reading order does not disagree with the visual one). It exists so the three inline editors (title, genre, word count) and their 585-line spec survive the re-cut.
- **⚠️ OPEN — THE ‘X MEETS Y’ PITCH LINE NOW RENDERS NOWHERE IN THE APP.** Its only renderers were `ManuscriptPitchPane`, `ManuscriptDetailTiles` and `ManuscriptCompsPane`, all deleted by this re-cut; the Comparable titles PAGE does not render it either. `src/lib/manuscriptTiles.ts` (which holds `PITCH_PHRASE`/`PITCH_LABEL`) is therefore UNREFERENCED ON PURPOSE, pending a decision. `bookProfile.test.tsx` asserts that state so it fails the day the line is rehomed or the module removed — both of which are answers.
- **Deleted with the re-cut** (recoverable at `34ff2de3`'s parent): `ManuscriptPitchPane`, `ManuscriptDetailTiles`, `ManuscriptPackagesPane`, `ManuscriptCompsPane`, `manuscriptMarks` and their five specs — 1,690 lines. Found by a fixed-point sweep, then confirmed symbol by symbol, because a grep for `MARK` matches forty unrelated files.
