## Shell nav v3 — the rail is places, pages are tabs, More is retired (13 Nov; ref design-refs/shell-nav-v3.html; report reports/shell-nav-v3/REPORT.md; branch `shell-nav-v3`, NOT merged)
- **Five sections, one list: `workspaceNav.workspaceSections`** — Dashboard · Queries (Query Centre, Responses, Analytics) · Agents (Contact list, Discover) · Materials (Query letters, Submission packages, Comparable titles, Versions, Manuscripts) · Tasks (`TODO_ROUTES`). "Your book" and "Founding writer" are gone from the nav; no page changed its address. Locks: SNV3-M1..M8 (`workspaceNav.test.ts`).
- **Why places, not pages, on the rail:** rail v2 put five *pages* on the rail and the rest behind More, so half the app was one hover away and More lit with a borrowed name. A row per section makes the rail a complete map again (every page is one row plus one tab away), and the tab strip already shows the section's pages, so More had nothing left to do. Deleted: `RailMore`, `railMore.css`, `railItems`, `moreGroups`, `morePageFor`, `railLabelOf`, the per-page `rail` / `railLabel` flags.
- **A rail row is lit on any page of its section; nothing is lit on /your-notes, Settings, Plans, Help or Import. A click goes to the section's `def`, or the first page not locked for this account (`railTargetFor`)** — a Free writer's Materials row lands on Manuscripts. No per-section memory of the last page. The rows have no tooltip (the label is on the row); the Tasks count stays. Locks: SNV3-R1..R5 (`navProMarks.test.tsx`), SR6.1/SR6.3 (`sidebarRail.measure.ts`).
- **Pro marks are the pages' own:** Query letters, Submission packages, Comparable titles carry `materials`; Versions `versions`; Discover `discover`; Manuscripts none. No section carries one (`ShellSection.pro` is deleted, and the full sidebar's heading tag with it). Locked pages are shown locked, never hidden.
- **The tab strip (`TabStrip` in `shell/FolderTab.tsx`): every page of the section, in nav order, which never changes; the current tab rises where it stands.** Values are the ref's `.tabs` / `.tab` / `.tab.cur` / `.fil` (inkShell.css, "SHELL NAV v3"): resting 34px, cream 14% ground, cream 90% text, 16px Special Elite; current 41px, `--ink-tab` paper, 19px, a 10px lane either side (none on the left when first). The fillet path is FolderTab's, verbatim: right always, mirrored left when not first. Tabs print `tabLabel` (Letters, Packages, Comps, Manuscript); `label` stays the full name for the palette, the title, crumbs and aria-labels. A nav landmark of buttons with `aria-current="page"` — not ARIA tabs. 150ms ease-out between tabs of one section, none under reduced motion. Locks: SNV3-T1..T5 (`tabStrip.test.tsx`), SNV3-E1/E2/F1/F2/E4 (`shellNavV3.measure.ts`).
- **No group label in the bar, anywhere** (Settings reads "Settings"). `/your-notes` names its tab from `OFF_NAV_NAMES`.
- **⚠️ The strip's measurer carries none of the live tab's hooks** (`.ws-ftab`, `.ws-ftn`, `data-tab`): its boxes are real, so a probe listing every sized `.ws-ftn` read the page name twice (calendarRetired L5 caught it).
- **Fit (`planStrip`): names → icons → "+N", resting tabs from the right; the current tab is never an icon or in "+N".** The strip also observes the bar's right group, because a late guide pill moves the search field without resizing it.
- **⚠️ "No resting tab left of the clicked one moves" cannot hold with the ref's values:** the old current tab shrinks when it settles (19→16px type, 22→16px padding, its lane goes), so every tab to its right moves left by that amount (measured in SNV3-E2). What holds, and is locked: the order never changes, and a tab left of both the old and the new current tab never moves.
- **The guide pill (`shell/guide/pageChecklist.css`) is the ref's `.b-guide`:** transparent, a cream 22% hairline, cream 90% 600 14px serif, the count in terracotta 400 13px, an 18px ring (cream 20% track, terracotta arc). The finished pill is the same outline (no sage fill), its ✓ and ring in `--sage`; the ref draws only the live one, and the e2e harness's finished Query Centre guide is what caught the fill. Locks: SNV3-P1 (e2e), SNV3-P2 (unit).
- **The ink account menu has "Your notes"** between Task settings and Help centre, with the nav's `notes` glyph and the sidebar link's "{n} new". Locks: SNV3-A1..A4, SNV3-A1e.
- **Left as they were, on purpose:** the full sidebar (it now shows four headings and thirteen rows; SR5 still fits at 1512×982), the ⌘K palette (Your notes is named in `PALETTE_PAGES` itself now), the settings rail, the phone shell — whose page title reads `workspacePageForPath`, so Manuscripts and Versions now name "Materials" as their section there. The onboarding frame (`SetupFrame`) still uses the old `FolderTab` with its group label ("Your account"); it is out of this pack's bounds.

## App shell — the desk, the capsules and the alignment contract (app-shell pack, 5 Aug; refs = design-refs/scriptally-sage-desk.html + scriptally-topnav-v2.html)
- **⚠️ THE ALIGNMENT CONTRACT IS A RULE, NOT A SET OF VALUES.** Four tokens expansion never touches — `--gutter` (20px, the icon box's x), `--icon` (38), `--pitch` (42, parent row), `--kid` (34, child row) — plus `--head` (72, driving BOTH capsules' headers) and `--col-min`/`--col-max` (78 ↔ 246). On expand **only labels, chevrons and children change; icons do not move.** Alignment is **structural, not maintained**: the icon sits at `--gutter` in both states because both read the same token, not because two numbers were matched by hand. **If a future change moves an icon between states, the token is being bypassed — that is the bug**, and the fix is to put the row back on the token, never to nudge the other state to match.
- **⚠️ `align-items: baseline` ON AN IMAGE ALIGNS ITS BOTTOM MARGIN EDGE — images have no baseline.** *(Measured 9 Aug: the pagebar wordmark sat **7.6px low** beside the crumb, and every value in the rule was the one intended.)* A row mixing **text and images** cannot be baselined: the text aligns on its baseline, the images on their bottoms, and the taller image drags. Two consequences that both bit in the same pass: the brand row uses **`align-items: center`** and pays for the optical difference with an explicit padding contract (19px top / 16px bottom) rather than by nudging one child; and **a text element that lands inside a baselined container inherits the trap** — the save state was 3.7px low as a `.ws-crumb` child and correct as a pagebar child, with no CSS of its own changed. **If a child is mysteriously low, check what its container aligns on before you touch the child.**
- **⚠️ THE DESK AND THE ACTIVE FILL ARE TWO TOKENS, and they used to be one.** `--shell-ground` was both the ground and the nav's active-row fill under the old law *"active = a window cut through to the page ground"*. **That law only held while the ground was neutral cream.** Cut a window through to sage and the metaphor produces a **green pill**. So: **`--shell-desk: #aebdb0`** is the ground and *nothing else reads it*; **`--shell-active-fill: #ffffff`** is the selector and every `.on` state. **THE LAW, RESTATED: active is a BRIGHT SURFACE LAID ON the capsule, not a hole cut through it.** The old sentence is deleted rather than left standing — it would re-generate the bug the next time someone touched it.
- **⚠️ It is `--shell-desk`, NOT `--desk`.** `--desk` was already taken: the per-theme working-area background (Capp `#e8ddd0` · Bold `#c2cfda` · Editorial `#f4f4f3`) that the hubs and the ultrawide margin rule read. A `:root --desk` would have been overridden by every theme class **silently** — the desk would just have come out the wrong colour with nothing to point at.
- **⚠️ THE SHELL RENDERS WHAT EXISTS, NEVER WHAT IS PLANNED.** *(Nick's own note: the pack's lists were written from the product he wants, not the routes we have.)* **Any nav list in a pack is a PROPOSAL to be checked against the router, not a specification.** Roughly half the top-nav's mega-menu items had no route — Progress, Archive, Agencies, wish lists, response times, Query letters, Synopses, Opening samples, Downloads — and every one is **absent**, not dead and not greyed: a nav item that goes nowhere teaches the wrong shape of the app, and a greyed one hints at a roadmap in the chrome. The rail follows the same rule, and **the two surfaces must not diverge** (locked: `topNav.test.tsx` asserts the rail's model has none of them either).
- **⚠️ THE TOP NAV HAS THREE HEADINGS — Queries · Agents · Materials.** `Learn` was dropped: its only real destination is Help centre, which the shared account menu already carries, so nothing became unreachable. **A heading that opens onto one link advertises a section that does not exist.** It returns when there are guides to put in it.
- **⚠️ MEGA-MENU COLUMNS COME FROM CONTENT, never three reserved slots** — three fixed columns holding two items looks broken, and the menus are thinner than the mockup drew them. One component, `--cols` set from the data. The right-hand **live-data panel stays in every menu** and now carries more weight than the mockup asked of it: it is what stops a short menu looking empty.
- **⚠️ AN INSET FILL NEEDS A SURFACE IT CAN ACTUALLY SIT ON.** `--shell-inset` (`#efe8df`) is **near-invisible on the column** (`#efe7db` — measured within 0.01 relative luminance) and **a real step on the content capsule** (`#f7f2e9`). So it is retired from the column and kept everywhere else. On the column, a control that needs to read as a surface takes **white fill + 1px `--shell-line` hairline** — which is what the ghost `Record a response` button already does. **Do not delete the token app-wide:** on menu and palette rows it is the hover, and replacing it there would put a bordered box under the pointer instead of a wash. *(Nothing needed deleting in the end — the column's only fills are the selector and that ghost button, so it already obeyed the rule; a lock now keeps it that way.)*
- **⚠️ HEADER HEIGHT ON A FIXED-HEIGHT MASTER–DETAIL SURFACE IS TAKEN DIRECTLY FROM THE PANES BELOW.** That is why `PageHeader`'s `compact` flag exists, and why it wins over the tool row: the row is the default layout, but **on a compact page the actions stay INLINE on the title row**, because giving them their own row adds back exactly the height compact was built to remove. One layout, one density flag — and the flag already governed alignment, so governing row-versus-inline is an extension rather than a new concept.
- **⚠️ THE SELECTOR NEVER MARKS A ROW THAT IS NOT RENDERED — a collapsed child resolves to its parent.** The floating selector is the column's ONLY active marker, so what it points at is the whole answer to "where am I". Children are hidden while the column is collapsed, so honouring a child target there would leave the one marker floating over a row that is not on screen. **A decision, not a missing case — do not "fix" it.** (`selectorBox`, locked as state four of four.)
- **⚠️ THE SHADOW TINT BELONGS TO THE DESK'S COLOUR FAMILY AND MOVES WITH IT.** Four stops, green-grey `rgba(56,66,58,…)` because the desk is sage. **A cool-blue or warm-brown shadow on a sage desk reads as dirt rather than depth.** The stops are just the shape; the tint is the rule. Capsules also carry a **white top rim** (`--shell-cap-rim`) — without it they read as holes cut in the desk rather than objects resting on it.
- **⚠️ THE MOCKUP-WINS RULE HAS ONE CARVE-OUT.** A mockup wins on **what it shows**, but **not where the pack names a value and gives its reason** — a reasoned value in prose beats an unreasoned one in an artefact. (Case in point: `scriptally-sage-desk.html` still ships a blue-grey `--lift` left over from the pastille sheet's blue desk. That line is **fenced as stale in the committed ref**; the shipped tint is green-grey.) Fence stale lines in place rather than editing the ref, per the house treatment of partially-current refs.
- **⚠️ CHECK FROM CONSUMPTION TO DEFINITION, NOT DEFINITION TO CONSUMPTION.** *(The finding of this project.)* `calc()` on an **undefined** custom property yields `NaN`, and CSS says nothing: the declaration is simply dropped. `--pad-r` was read by four rules — including the shell selector's width — while being defined nowhere, so **the only active marker in the shell rendered 0px wide** with **tsc, 2,259 tests and a production build all green**.
  - **Why the obvious guard missed it:** the earlier rule was *grep `dist/` for the tokens you added*. **Checking that what you wrote arrived cannot catch what you referenced and never wrote.** The direction was wrong, not the idea.
  - **The rule:** every `var(--x)` a stylesheet READS must resolve to a definition — asserted in `shellV2Tokens.test.ts` ("no shell rule reads a token that does not exist"). Pointed this way it immediately found two more: `--sv2-flank`, left dangling when Phase 3 deleted `.sv2-tb-dash`, and `--shell-ease`, which named nothing behind an inline fallback.
  - Still also grep `dist/` after adding or renaming a token — a green build proves the CSS parsed, not that it contains what you wrote (see the swallowed-comment note below). The two guards catch opposite mistakes.
- **⚠️ A PSEUDO-ELEMENT KEEPS ITS OWN TRANSITION.** Suppressing the transition on `.x` does NOT reach `.x::after` — target it directly (`.x::after { transition: none !important }`). The top-nav hairline measured opacity `0` in BOTH states and looked like a dead rule; it is 0 → 1.
- **⚠️ AND AN ELEMENT MID-ENTRANCE REPORTS ITS ANIMATED BOX, SO MEASURE AFTER `animationend` OR WITH ANIMATIONS OFF — NEVER DURING.** *(21 Sep, the task modal.)* It measured **674px** on one run and **680** on the next with no change between them: `getBoundingClientRect` on an element still inside its `scale(.975)` entrance returns the SCALED box, and 680 × 0.99 is 674. The reading was the harness's, not the page's — and it is the more dangerous half of the family below, because a plausible number about a correct page gets believed. Wait for `animationend`, set `animation: none`, or poll until two consecutive reads agree.
- **⚠️ SUPPRESS TRANSITIONS BEFORE MEASURING — a transitioned property reports where it STARTED, not where it is.** This has now cost time twice, and both times it looked like a real bug: a **collapsed column measured 246px** (its expanded width) and **the fade's opacity measured 0** while its class was on. Set `el.style.transition = "none"` before reading, or read after the transition has demonstrably finished. In the in-app browser pane specifically, transitions do not reliably advance at all, so `getComputedStyle` returns the start value indefinitely.
- **⚠️ A CUSTOM PROPERTY COMPUTED AT `:root` CANNOT BE OVERRIDDEN BY A LOWER VARIANT; ONE READ INSIDE A `calc()` RESOLVES AT THE USE SITE.** *(Query Centre, 13 Aug — and the two look identical from a distance, which is the whole cost.)* `:root` sets `--content-top-gap: var(--content-top-gap-rest)`, so the value is **already resolved** by the time any page sees it: overriding `--content-top-gap-rest` further down changes **nothing**, and the page-scoped rhythm had to name `--content-top-gap` itself in both states at 0-2-0. `--header-inset` is read inside `calc(var(--content-gutter) + var(--header-inset))` on `.wpg-plate`, so a **use-site** resolution — overriding it on an ancestor works, and one page-scoped line took the masthead from a 120px-inset island to a full-width band without touching the shell's law or the other nine pages. **The test is not "is it a token" but "where is it evaluated": a variant read into a resolved property at `:root` is spent; a property read inside a `calc()` is live all the way down.**
- **⚠️ A MALFORMED CSS COMMENT SWALLOWS TOKENS SILENTLY.** A declaration left outside its `/* */` produced **no token and no error** — the build succeeded, the tests passed, and the desk was simply the wrong colour. Every shell token now sits in `shellV2Tokens.test.ts`'s `BAKED` map for exactly this reason: a value asserted there fails the moment it stops being emitted.

## Navigation & shell architecture (post-AppShell rollout `88db5f7`+`4933aca`, live on prod)
- **⚠️ THE BREADCRUMB IS CHROME — A PAGE MUST NEVER RENDER ITS OWN (app shell v2, 9 Aug).** It is
  drawn once by `WorkspaceShell`, on the page ground ABOVE the content window, from the pure
  `shellCrumb`. It therefore does NOT scroll with the content. A page drawing its own would give
  two crumbs that disagree the moment a route's naming changes. If a page needs different words,
  the fix is `shellCrumb`'s table — never a local render.
- **Global shell = `src/components/shell/AppShell.tsx`**, rendered once: persistent left rail (240px ↔ 60px via the edge chevron; state in `localStorage["scriptally.queriesRailCollapsed"]`), never remounts on navigation. The desktop top bar is RETIRED — `Nav.tsx` survives only as the below-`md` mobile slim bar (alongside `BottomTabBar`). **The rail's anatomy was REBUILT 5 Jul (grouped index + capture + utility — see the Rail rebuild section below); the old flat-four-items + bell/settings icon-row description is superseded.**
- **Routing = `react-router-dom` (BrowserRouter).** New code uses the router directly; `handleNavigate(tab, sub?)` in `App.tsx` is a bridge (`pathFor`) for legacy call sites. The three focus-form interceptions ("Log a query"/"Send a query", "Add an agent", "Add a manuscript"/"Add a Manuscript") open overlays and NEVER navigate; `searchQuery` clears on real navigation only.
- **Route map (now TIERED — see the Route tiers section):** workspace `/dashboard` · `/queries` (`?q=<id>` deep-selection, `?view=landing` legacy) · `/agents` · `/agents/discover` · `/manuscripts` · `/manuscripts/packages` · `/import` (+ guarded `/email-import-dev`); marketing `/` (Landing) · `/pricing` (Pricing); focus `/account` · `/plans` (PlansPage — a DISTINCT page from Pricing; consolidation is an open decision, never merge silently) · `/help`. Unknown paths → `/dashboard`. Pre-auth `#/login`/`#/signin`/`#/signup` and the DEV-only lab hashes coexist with the router (hash ≠ pathname); hosting rewrites (`** → /index.html`) cover deep links.
- **Main pages stay MOUNTED** — dashboard/queries/agents/manuscripts are persistent `StagePage` slots (display toggling). Page-local state (Queries filters/sort/selection) must survive navigation — never "fix" by unmounting. StagePage's enter-animation class self-clears (animationend + 250ms timeout): while it runs, its transform makes the slot the containing block for `position:fixed` page furniture — do not simplify that away.
- **The stage (`#app-stage-scroll`) is the scroll container**, not the window. Page heights are stage-relative — no `calc(100vh - 64px)`-style bar offsets, ever. Overlay scroll locks go through `src/lib/stageScroll.ts` (stage + body, wedge-proof release), never `document.body`/`window.scrollY` alone. Per-route scroll position is remembered on the stage element.
- **Themes:** the `.t-capp`/`.t-bold`/… class lives on the AppShell ROOT; tokens in `index.css` (incl. `--navpill`); persisted in the user doc `queriesTheme`; two controls (rail-foot seg + Settings radio) write the same field. Form 11 inset frame is Cappuccino-only (`.t-capp .qhbar::after`). The rail chrome is themed on every page; non-Queries page interiors keep hard-coded styling until the parked page-unification phase.
- **Shell CSS footgun:** the rail's and help-FAB's `display` comes from classes + media queries, NOT inline (inline display beats Tailwind breakpoint utilities); the rail collapse rules need `!important` against inline-critical styles.
