- **The live face never mounts while the flag is off, except through the dev review aid** (`lib/discoverReviewAid`: `window.__SA_DV_STATE = "live"|"done"|"none"|"empty"` over a fixture in memory, `__SA_DV_LIVE = 1` over the real account, `__SA_DV_HOLD_MS` to hold the loading face). **The page names the aid only in `import.meta.env.MODE !== "production" ? devAid() : NO_AID`.** ⚠️ An early return inside a function was NOT folded, and the aid's module-scope fixture was kept as a side effect — both shipped to production until lock E1 grepped the bundle. - **The data:** `users/{uid}/scoutDecisions/{communityAgentId}` (`added` | `passed` + `until` a year on; "Skip for now" is never stored; Bring back and Undo delete or restore it) · `discoverPrefs` on the user doc (lens + three switches, written leaf by leaf) · `agentSubmissions/{uid}_{sourceAgentId}` (create only, public fields only, admin reads) · `users/{uid}/scoutShares/{sourceAgentId}` (the writer's own echo). Pure derivations in `lib/scout.ts`; all IO through one `ScoutIO` (`lib/scoutStore.ts`), which the review aid swaps for an in-memory store.
- **⚠️ UNDO IS A SNAPSHOT AND THE CATALOGUE'S +1 IS HELD.** A client may only `+1` `contributedByCount`, never take it back, so the bump waits until the add stands (the toast's life, or the page left / tab hidden). Undo deletes the agent, its `act-added-agent-{id}` row and the decision — or restores an overwritten expired pass.
- **⚠️ A SHARE CANNOT BE TAKEN BACK BY THE CLIENT, so the sheet says so and the toast offers no Undo.**
- **⚠️ EVERY CATALOGUE FIGURE IS ABSENT** (`catalogueFigures()` returns nulls). The catalogue collection is readable, but `db.tsx` silently falls back to the local seed list on a failed read, so counting it could state the seed's numbers as live. Wiring a source is that one function.
- **The pick queue:** verified (`lastVerifiedDate` present) agents whose genres take the book, not decided (added, or passed and in date), the switches, ranked by the lens through `rankEntries`. A genre fit alone is picked (as "possible") — `buildDiscoverEntries`'s threshold would have dropped every one. A lens the catalogue cannot back reads as "best".
